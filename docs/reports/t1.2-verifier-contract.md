## 0. 一句话

`verify_generation.py` 是流水线的**强制关卡**：CubeMX 说"生成成功"不算成功，只有它报 `verdict=pass` 才算。
`regen.sh` 把"备份 → 生成 → 核验 → 失败回滚"合成一条命令，任何一步不过都回到生成前的 `.ioc`。

## 1. `scripts/verify_generation.py`

### 1.1 CLI（参数名是契约，勿改）

```
python scripts/verify_generation.py \
    --log <cubeMX生成日志路径> \
    --main-c <工程/Core/Src/main.c> \
    --mxproject <工程/.mxproject> \
    --expect <外设名逗号分隔, 如 GPIO,TIM4,USART2> \
    [--allow-signal VP_RIF_VS_RIF1] \
    [--json-out <输出路径>] \
    [--report-md <输出路径>]
```

| 参数 | 必填 | 说明 |
|---|---|---|
| `--log` | ✅ | CubeMX 生成日志（`regen.sh` 用 `-q` 模式的 stdout/stderr 全量重定向，约 200KB） |
| `--main-c` | ✅ | 生成的 `Core/Src/main.c`（**唯一**能证明外设是否真的被生成的文件） |
| `--mxproject` | ✅ | 生成的 `.mxproject`（查盘符绝对路径） |
| `--expect` | ✅ | 期望外设清单；逗号/分号/空白分隔，大小写不敏感，自动去重转大写；传空串 `""` 表示"不检查外设" |
| `--allow-signal` | ❌ | `Cannot map` 白名单，**可重复、可逗号分隔**。命中白名单的行降级为 `warn` |
| `--json-out` | ❌ | 结构化 JSON 报告路径（自动建父目录） |
| `--report-md` | ❌ | Markdown 报告路径（含表格，适合直接贴进证据文档） |
| `--version` | ❌ | 打印版本与 schema |

**白名单没有内置默认值**：不给 `--allow-signal` 时任何一条 `Cannot map` 都判 `fail`。
D8 的 `VP_RIF_VS_RIF1` 是**项目级**已知噪音，由 `regen.sh` 默认预置（见 §3.2），而不是核验器默默放过。

### 1.2 退出码

| 码 | 含义 | 下游动作 |
|---|---|---|
| `0` | 全部通过（**允许** `warn` 级问题，如 D9） | 可继续 `pio run` |
| `1` | 存在 `fail` 级问题（静默丢弃 / 不可复现路径） | **禁止**继续，必须回滚或修 `.ioc` |
| `2` | 输入/IO/参数错误（文件不存在、读不了、报告写不了） | 修命令，不代表配置有问题 |

### 1.3 JSON schema：`platform32.verify_generation/1`

```json
{
  "schema": "platform32.verify_generation/1",
  "verdict": "pass",
  "checks": [
    {"id": "log_cannot_map", "status": "pass", "level": "error", "detail": "生成日志无 'Cannot map' 命中（另有 1 条 OptionalMessage_ERROR …）"},
    {"id": "main_init_present", "status": "pass", "level": "error", "detail": "全部 1 个期望外设都有初始化函数定义：GPIO → MX_GPIO_Init（exact，定义 L152）"},
    {"id": "main_init_called", "status": "pass", "level": "error", "detail": "全部 1 个初始化函数都在 main() 内被调用：GPIO → MX_GPIO_Init（调用 L88）"},
    {"id": "mxproject_abs_path", "status": "pass", "level": "error", "detail": "'.mxproject' 无盘符绝对路径（换机可复现）"},
    {"id": "syscalls_path", "status": "pass", "level": "error", "detail": "生成日志无 syscalls.c / sysmem.c 叠加路径异常"}
  ],
  "summary": {"errors": 0, "warnings": 0, "checked_peripherals": ["GPIO"]},
  "inputs": {"log": "…/cubemx-generate.log", "main_c": "…/Core/Src/main.c", "mxproject": "…/.mxproject"},
  "expect": ["GPIO"],
  "allow_signals": ["VP_RIF_VS_RIF1"],
  "tool": {"name": "verify_generation.py", "version": "1.0.0"}
}
```

字段约束（下游可依赖）：

- `checks` **恒为 5 条**，顺序固定为 `log_cannot_map` → `main_init_present` → `main_init_called` → `mxproject_abs_path` → `syscalls_path`；id 不得改名。
- `status ∈ {pass, warn, fail, skip}`；`level ∈ {error, warning}`，`level=warning` 当且仅当 `status ∈ {warn, skip}`。
- `verdict = "fail"` 当且仅当 `summary.errors > 0`；`warn` / `skip` **不影响** verdict。
- `summary.errors` = `status=fail` 条数；`summary.warnings` = `status=warn` 条数；`summary.checked_peripherals` = 规范化后的 `--expect`。
- `inputs` 内是**绝对路径**（`os.path.abspath`）。
- 额外字段 `expect` / `allow_signals` / `tool` 是给证据链留痕的，属新增字段，消费方可忽略。
- JSON 里**不含时间戳**（便于 diff 与快照比对）；时间戳只出现在 Markdown 报告里。

### 1.4 五个 check id 的判定逻辑

#### `log_cannot_map` — 外设被静默丢弃的根因证据（D5 / H-6）

- 逐行匹配 `cannot\s+map`（大小写不敏感），记录行号与原文。
- 命中行里若包含任一 `--allow-signal` 值（子串、大小写不敏感）→ 该行降级；全部命中行都被降级 → `warn`，否则 `fail`。
- 日志为**空/纯空白** → `warn`（"没错误"不能靠一份空日志证明）。
- `OptionalMessage_ERROR` 行**不参与判定**，只在 detail 里报数量：G474 最小工程必有一条 `VP_RIF_VS_RIF1` 噪音（D8），判它等于永远报错。
- `warn` 是**预期行为**而非缺陷：`detail` 里写明放行了哪个信号、在哪一行。

#### `main_init_present` — 期望外设是否真的有初始化函数**定义**

- 先对 `main.c` 做**注释/字符串剥离**（保留换行，行号不变），再解析，避免把注释里的"死定义"当成定义。
- 判定为定义的条件：`MX_<...>_Init(...)` 后面跟 `{`；跟 `;` 的是原型声明，不算。
- 外设 → 符号的**容错匹配**（顺序即优先级，全部大小写不敏感）：
  1. 精确 `MX_<PERIPH>_Init`（`GPIO` → `MX_GPIO_Init`）；
  2. 带功能后缀 `MX_<PERIPH>_<FUNC>_Init`，`FUNC ∈ {UART, USART, LPUART, TIM, SPI, I2C, ADC, DAC, CAN, Device, Host, SD, ETH, SAI, I2S, RTC, FLASH, USB, COMP, OPAMP, CRC, RNG, HCD}`（`USART2` → `MX_USART2_UART_Init`、`USB` → `MX_USB_Device_Init`）；
  3. 兜底：`MX_<PERIPH>_<TOKEN>_Init` 且**唯一**命中时接受（标 `fuzzy`）；多个候选时报歧义、判缺失。
- **不做子树误匹配**：`--expect TIM` 不会匹配 `MX_TIM4_Init`（否则"少配一个定时器"会被漏报）。
- `detail` 必须写出实际匹配到的符号名与匹配方式、定义行号 —— 这是人工复核与 S1 场景写证据的直接依据。
- 无 `--expect` → `skip`。

#### `main_init_called` — 初始化函数是否在 `main()` 体内**被调用**

- 用大括号配平定位 `int main(void) { … }` 的体区间；找不到 `main` → `fail`（无法证明会被执行）。
- 在体区间内搜 `\b<symbol>\s*\(`；因为注释已剥离，`/* MX_TIM4_Init(); */` **不算调用**。
- 只核验"确实有定义"的符号：没定义的外设已在 `main_init_present` 报过 fail，这里不重复报（detail 会写"另有 N 个外设无定义、未参与本项"）。
- 一个定义的都没有 → `skip`（`level=warning`），避免同一个根因报两条 fail。
- 无 `--expect` → `skip`。

#### `mxproject_abs_path` — 换机可复现性（TOOLING §3.2）

- 逐行匹配 `(?<![A-Za-z0-9])[A-Za-z]:[\\/]`；命中即 `fail`，detail 报行号与截短后的行内容。
- 反向断言挡掉 `http://`、`file:///` 这类伪盘符（已单测覆盖）。
- 只判盘符路径，不判 UNC（`\\server\share`）与相对路径。

#### `syscalls_path` — D9 已知缺陷，**只降级为 warning**

- 行内同时出现 `syscalls.c` / `sysmem.c` **且**出现 `FileNotFoundException|IOException|Exception|拒绝访问|access is denied|cannot find|no such file` → `warn`。
- 只是**永不** `fail`：这两份 newlib 桩改动极少，CubeMX 叠加路径是工具缺陷，不该让流水线卡死（调研报告 §7 风险条）。
- `detail` 写明"需要更新时从 FW 包的模板目录复制"，并标注 D9。

## 2. `scripts/ioc_backup.py`（git 之外的第二道保险）

```
python scripts/ioc_backup.py --project <工程目录> [--list] [--restore] [--json-out <path>]
```

| 行为 | 说明 |
|---|---|
| 默认（备份） | 工程顶层每个 `*.ioc` 复制为 `<name>.ioc.bak`；临时文件 + `os.replace` 原子落盘；记录字节数与 sha256 |
| `--list` | 只列出 `*.ioc`，**不写盘**（只读审计用） |
| `--restore` | 从 `<name>.ioc.bak` 还原（非 git 工程的回滚通道） |
| `--json-out` | 结构化输出，schema `platform32.ioc_backup/1`，含 `files[].sha256` 便于校验回滚是否真的回到原状 |

退出码：`0` 成功 / `1` 未找到 `.ioc`（或还原时缺 `.bak`）/ `2` 参数或 IO 错误。
`.ioc.bak` 已被模板 `.gitignore` 的 `*.ioc.bak` 规则忽略，不会污染 `git status`。

## 3. `scripts/regen.sh`（T1.3）

### 3.1 用法

```
scripts/regen.sh <工程目录> [选项]
```

| 选项 | 说明 |
|---|---|
| `-e, --expect <list>` | 期望外设；**默认从 `.ioc` 的 `Mcu.IP*` 推导**（滤掉 `NVIC/RCC/SYS/DBGMCU`）再补 `GPIO` |
| `-l, --log <path>` | 生成日志路径（默认 `<out>/cubemx-generate.log`） |
| `-m, --mx <script.mx>` | CubeMX 脚本（默认 `<工程>/scripts/cubemx-generate.mx`，找不到则在 `<工程>/scripts/*.mx` 里取第一个） |
| `-o, --out <dir>` | 证据输出目录（默认 `${TMPDIR:-/tmp}/platform32-regen`，**故意不落在工程里**，避免污染 `git status`） |
| `--java` / `--cube` | 覆盖解释器/exe 路径（默认读 `$ST_CUBEMX_JRE` / `$ST_CUBEMX_EXE`，否则 `C:/ST/STM32CubeMX/...`） |
| `--timeout <sec>` | 生成超时，**最小 240**（低于自动抬到 240 并告警）；默认 300 |
| `--allow-signal <sig>` | 透传给核验器；**默认已预置 `VP_RIF_VS_RIF1`**（D8） |
| `--no-default-allow` | 不预置 D8 白名单（严格模式） |
| `--allow-dirty-ioc` | 允许 `.ioc` 处于未提交改动时继续（默认**拒绝**） |
| `--skip-generate` | 跳过生成，只做备份 + 核验（改完 `.ioc` 想单独重核验时用） |
| `--dry-run` | 只打印将执行的命令，不落盘 |

### 3.2 流程与安全语义

1. **前置检查**：工程目录存在、有 `*.ioc`、`Core/Src/main.c` 与 `.mxproject` 已存在、`.mx` 存在。
2. **git 干净检查**：`.ioc` 有未提交改动 → **直接退出 2**（因为回滚会丢用户改动）。这是调研报告 C5"回滚粒度是 git"的前置条件。
3. **D7 预警**：`.ioc` 里 `ProjectManager.AskForMigrate=true` → 告警提示无头生成可能卡在迁移框；**脚本不做文本注入**（红线），只提示人工改成 `false`。
4. **备份**：`ioc_backup.py` → `<工程>/<name>.ioc.bak` + `<out>/ioc-backup.json`。
5. **生成**：`cd <工程> && timeout 300 <jre>/java.exe -jar <cube>.exe -q <script.mx>`，stdout+stderr 全量进 `<out>/cubemx-generate.log`（工作目录必须是工程根，`config load` 用的是相对 `.ioc` 路径）。
6. **核验**：`verify_generation.py` + `--json-out <out>/verify.json` + `--report-md <out>/verify.md`。
7. **回滚**（生成失败或核验退出码非 0）：`git checkout -- '*.ioc'`，并对已入库的 `.mxproject` 一并 `git checkout`（防止盘符绝对路径留在工作区）；非 git 工程退化为 `ioc_backup.py --restore`；回滚后打印 `git status`。

**不做的两件事**（红线）：

- 不在 `.ioc` 上做文本注入（改配置只走 CubeMX CLI `set` / MCP）。
- 不"智能修复"配置：失败就是回滚 + 报错，不猜用户想配什么。

### 3.3 退出码

`0` 通过 / `1` 生成失败或核验 fail（**已回滚**）/ `2` 参数、IO、环境错误（java/CubeMX/.mx 缺失、`.ioc` 脏）。

## 6. 遗留风险与边界

| 项 | 影响 | 现状 |
|---|---|---|
| 核验只读 3 份产物（日志 / `main.c` / `.mxproject`） | 外设配了但参数被静默忽略（如 `Prescaler` 没进 `IPParameters`）时，只要 `MX_xxx_Init` 存在就能过 | 已知边界。要抓参数级漏配需比对 `.ioc` 白名单与 `main.c` 赋值，属 v2 范围，未做 |
| `.mxproject` 只判盘符路径 | UNC（`\\server\share`）不判 | 可接受；本机模板流不会产生 UNC |
| 回滚不覆盖 `Core/**` | 失败后 `Core/` 仍是本次生成结果 | 与 T1.3 DoD 一致；`Core/` 可由 `git checkout` 或再次成功生成恢复 |
| `AskForMigrate` 只能告警 | 若 CubeMX 真的卡在迁移框，只能等 `--timeout` 到点后失败 | 脚本不做文本注入（红线）；处置写进 SKILL.md |
| 符号容错是启发式 | 极端命名（如 `MX_<P>_<A>_<B>_Init`）需靠 `fuzzy` 唯一命中；多候选会判缺失 | 宁可误报（fail）也不静默放过，方向正确 |
| 真生成依赖本机 SDk | 只在 G474（FW_G4 V1.6.3 已装）验证过；F103/H723 未实跑 | F103 可直接跑；H723 需先装 FW_H7（T2.2 已挂起） |

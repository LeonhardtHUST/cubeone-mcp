### 2.2 审计发现（引脚层）

1. **`GPIO_Label` 数量 = 0**（`grep -c GPIO_Label` 返回 0）。19 个物理引脚**全部没有用户标签**，引脚语义 100% 靠用户代码维护。→ **审计结论**：本仓的引脚用途**无法从 `.ioc` 单独推断**，必须结合 `Core/Src/display.c` / `power_ctrl.c`。若后续要对本类工程做"配置级语义审计"，建议规范里加一条"关键引脚必须设 `GPIO_Label`"。（本次不擅自添加，属用户仓库设计选择。）
2. **SPI1 是"单向 2 线"配置，PA6 (MISO) 未分配**：引脚 Mode 标 `TX_Only_Simplex_Unidirect_Master`，但 `MX_SPI1_Init()` 里 `Direction = SPI_DIRECTION_2LINES`、`NSS = SPI_NSS_SOFT`。这是 CubeMX 常见的"引脚按单向选、IP 按双向生成"组合，功能上等价于只用 MOSI 发送（SCK+MOSI 有效，MISO 悬空不读），**不构成缺陷**，但审计时必须成对记录 `Mode` 与 `Direction` 两个来源，只看一个会误判。
3. **PB12/PB13 被当作普通 GPIO 输出**：在 F103 上 PB12/PB13 是 SPI2_NSS/SPI2_SCK 的默认复用位，这里配置为 `GPIO_Output`。说明显示驱动是"GPIO 并行/软件时序"而非 SPI2。与 SPI1 的存在不矛盾（SPI1 可能驱动另一颗器件）。
4. **无 NSS 引脚**：`SPI_NSS_SOFT` + 片选走 PA4 (GPIO_Output)。→ 审计 SPI 时必须查"片选由谁驱动"，`.ioc` 不会给出这种关联。

### 3.3 实际生效时钟（以 `Core/Src/main.c::SystemClock_Config()` 为权威，`.ioc` 未表达）

`.ioc` 里没有 SYSCLK/分频键，含义只能从生成代码反推 —— 这正是调研报告 C4"不能指望 `.ioc` 独立校验时钟"的实证：

```c
RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSI;   // ← 只有 HSI，HSE 未被启用
RCC_OscInitStruct.HSIState       = RCC_HSI_ON;
RCC_OscInitStruct.HSICalibrationValue = RCC_HSICALIBRATION_DEFAULT;
RCC_OscInitStruct.PLL.PLLState   = RCC_PLL_NONE;             // ← PLL 关闭
RCC_ClkInitStruct.SYSCLKSource   = RCC_SYSCLKSOURCE_HSI;
RCC_ClkInitStruct.AHBCLKDivider  = RCC_SYSCLK_DIV1;
RCC_ClkInitStruct.APB1CLKDivider = RCC_HCLK_DIV1;
RCC_ClkInitStruct.APB2CLKDivider = RCC_HCLK_DIV1;
HAL_RCC_ClockConfig(&RCC_ClkInitStruct, FLASH_LATENCY_0);
```

| 时钟 | 实际值 | 来源 |
|---|---|---|
| SYSCLK | **HSI 8 MHz**（内部 RC，±1% @25 ℃） | `RCC_SYSCLKSOURCE_HSI` |
| HCLK (AHB) | **8 MHz** | `DIV1` |
| PCLK1 (APB1) | **8 MHz** | `HCLK_DIV1` |
| PCLK2 (APB2) | **8 MHz** | `HCLK_DIV1` |
| PLL | **关闭**（`RCC_PLL_NONE`） | — |
| Flash 等待周期 | **0 WS** | `FLASH_LATENCY_0` |
| TIMxCLK | 8 MHz | `RCC.TimSysFreq_Value` |

### 3.4 时钟审计发现

1. **`RCC.HSE_VALUE=8000000` 是残留值，HSE 实际完全未启用**。`OscillatorType` 只有 `RCC_OSCILLATORTYPE_HSI`，`PLLState=RCC_PLL_NONE`。→ **只看 `.ioc` 的 `HSE_VALUE` 会得出"用外部 8 MHz 晶振"的错误结论**。这是本次审计最重要的一条：**`.ioc` 的 RCC 键是不可信的推断源，必须与生成代码交叉核对**。
2. **跑在 8 MHz，F103C8 的 72 MHz 上限只用了 11%**。性能余量 9× 未用（数字钟 + SPI 显示屏场景通常不需要，属合理取舍，但需在 "已知限制" 里写明，避免后续误判"板子慢"）。
3. **用 HSI 而非 HSE**：HSI 精度 ±1%（全温区更差），对"数字钟"这类**依赖时基守时**的应用是**精度风险**（按 ±1% 算，一天可累积约 14 分钟误差）。若该钟用 SysTick 计时而无外部 RTC 校准，守时精度不可接受 —— **属功能性观察，非构建问题**，建议转告用户（本报告不擅自改配置）。
4. `RCC.PLLMCOFreq_Value=4000000` = HSI/2，MCO 未引到引脚，纯计算残留值。

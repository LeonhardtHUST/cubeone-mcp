## 这个版本修了什么

M1「接缝修复」批次，全部来自 2026-11-03 交付审定的 🟡 项。**无破坏性变更**：默认行为与 0.6.1 一致。

### 代码

- **退出码映射白名单化**（审定 F1，最重要代码发现）。旧实现只认 `exit 2`，于是：WindowsApps 的 Python 商店桩 `exit 9009` 被当成"域内结论"；Python 未捕获异常 `exit 1` 的 traceback 混进正文当配置问题。新判据：`0`=成功；`1`=域内结论**当且仅当**落了结构化 JSON（或命中脚本的 `[<tool>][not-found]` 标记）且 stderr 无 `Traceback`；其余一切码（`2`/`9009`/未知）与超时/信号杀死一律 `isError=true`。
- **子进程注入 `PYTHONIOENCODING=utf-8`**（F2）。中文 Windows 默认 cp936，脚本 stderr 的中文按 utf8 解码会变乱码。
- **工具入口执行 `inputSchema` 校验**（U4.4 唯一 FAIL）。缺 `log`/`main_c` 等必填参数时不再把 `undefined` 拼进命令行、由 Python 报出"文件不存在：undefined"这类误导消息，而是在 MCP 层直接返回参数错误清单。含 enum 与类型抽查、`ioc_field action=set` 的 `value` 条件必填。
- **`ioc_field` 位置参数加 `--` 分隔**（F9/Y3）。`value` 以 `-`/`--` 开头时旧实现会被 argparse 当选项：`-h` 变成打印 help（假成功）、`--dry-run` 静默改写盘语义。现在选项一律前置、`--` 之后只放位置参数；`--json-out` 相应前置到 `--` 之前。
- **未知工具消息**附带可用工具清单（动态生成）。

### 测试与 CI

- 新增 **Node 层单测 32 例**（`tests/node/server.test.mjs`，`node:test` 零依赖）：退出码矩阵、路径白名单（前缀撞车 / `..` 越界 / win32 大小写 / roots 未设）、`buildArgs` 的 `--` 分隔、`validateArgs`、真实 stdio e2e、`CUBEONE_REQUIRE_ROOTS` 启动期行为。**补上了"安全门禁在 JS 侧却零测试"的缺口**（审定 F4）。
- CI 新增 `node` job（Node **18/20/22** 三档矩阵）。18 是 `engines` 下限，只测 20/22 等于没测下限。

### 发布物与文档

- npm 包 `files` 补 `scripts/regen.sh`（SKILL.md 称其"唯一不可替代"）与 `docs/guides/mcp-registration.md`（SKILL.md §0.1 引用了它，此前 npm 用户看不到）。
- **白名单未设置的警告显式化**：返回文本的 `allowed_roots` 从"未设置(不校验)"改为"未设置(本次调用无路径限制，见 README 安全节)"；新增 **opt-in** 严格模式 `CUBEONE_REQUIRE_ROOTS=1`——设置后若未配白名单，server **启动即退出**（stderr 给配置方法），而不是静默 fail-open。**默认不变**，0.7.0 才会把 fail-closed 变成默认。
- 治理回填（同批入库）：D33 追溯认定 npm 工具通道为正式交付物形态 + 版本轴治理规则；D34 见后续版本。

## 已知限制（如实记录）

1. **`PYTHONIOENCODING` 修复在本机无法复现验证**：本机 ANSI 代码页已是 `cp65001`，且环境已注入 `PYTHONUTF8=1`/`LC_ALL`，三组对照都造不出 cp936 分支。属"验证对象在本机不可达"，不是纸面修复；T10 断言留作回归守卫，需在真实 cp936 机器上才能体现效果。
2. **`CUBEONE_ALLOWED_ROOTS` 未设置时仍是 fail-open**（无路径限制，仅回显警告）。这是 0.6.2 的**有意保留**，让现有用户不被突然锁死；0.7.0 改为 fail-closed 并保留显式逃生门。
3. **npm 包不含 `package-lock.json`**：本仓 `.gitignore:49` 忽略了它，CI 因此用 `npm install` 而非 `npm ci`。依赖 `@modelcontextprotocol/sdk` 在 `package.json` 中钉的是精确版本 `1.32.2`，解析结果仍然确定。
4. **`node --test <目录>` 跨版本不可移植**：Node 22（Windows）会把目录当模块加载报 `MODULE_NOT_FOUND`，Node 18 则递归展开。CI 与文档统一改用 `tests/node/*.test.mjs`。

## 升级说明

`npm i -g cubeone-mcp@0.6.2` 或把 MCP 注册条目里的版本号改为 `0.6.2`（或用 `@latest`）。三个脚本仍是纯标准库，无需 `pip install`。

若你依赖"`ioc_field get` 查不到键时 `isError=false`"这一行为：**本版保持**（`[not-found]` 标记被显式列入域内结论）。若你依赖"任何 `exit 1` 都不算错误"：**本版收紧了**，裸 `exit 1`（崩溃/依赖缺失）现在会报 `isError=true` 并标注"执行层失败"——这是修复，不是回归。

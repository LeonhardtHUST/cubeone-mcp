## ⚠️ BREAKING：路径白名单默认值翻转

**`CUBEONE_ALLOWED_ROOTS` 未设置 = 拒绝所有路径参数**（0.6.x 是"未设 = 不校验"）。

### 为什么必须破坏

0.6.x 的默认值让"能跑通"被误当成"被限制住了"：用户看到工具正常返回，就以为路径在白名单内，
而实际上 agent 的每一次笔误（写错工程目录、跟错 junction）都能落到任意位置，**全程处于无保护状态却不自知**。
默认值不会自己说话——只有写下来的放宽才会被看见、被复核。所以 0.7.0 把代价从"所有人静默无保护"
换成"需要放宽的人写一行 env"。

### 迁移（改完重启 MCP 客户端，二选一）

```jsonc
// 推荐：配白名单。Windows 用 ';' 分隔，POSIX 用 ':'
"cubeone-mcp": {
  "command": "vpx",
  "args": ["cubeone-mcp"],
  "env": {
    "CUBEONE_POLICY": "read_only",
    "CUBEONE_ALLOWED_ROOTS": "D:\\Projects;C:\\Users\\you\\WorkBuddy"
  }
}
```

```jsonc
// 不推荐：显式退回 0.6.x 的宽松语义（确实需要访问任意路径时）
"env": { "CUBEONE_ALLOW_NO_ROOTS": "1" }
```

`CUBEONE_REQUIRE_ROOTS=1` 仍可用但**降级为冗余**（默认已严格）：设不设都不改变路径判定，只额外提供
"启动即退出"的 fail-fast。它与 `CUBEONE_ALLOW_NO_ROOTS` 同时为真时**以后者为准**（显式放宽优先）。

## 这个版本改了什么

### 路径白名单改为 fail-closed（R-C1 第二步）

- 未配白名单 → 每次带路径参数的调用返回 `[cubeone-mcp][策略拦截] 未配置 CUBEONE_ALLOWED_ROOTS，0.7.0 起默认拒绝所有路径参数。`，文案给出两种出路（配白名单 / 显式开逃生门）。
- 宽松模式**必须自曝**：脚注回显 `allowed_roots=未设置(宽松模式：本次调用无路径限制，CUBEONE_ALLOW_NO_ROOTS 生效)`——静默放宽等于没有放宽可言。
- 启动横幅区分三态：严格有白名单 / 严格无白名单（等于全拒）/ 宽松模式。

### 白名单改为比较物理路径（R-C2，防 junction / symlink 绕出）

- 白名单目录与目标路径**双侧**取 `realpath` 后再比较。`mklink /J` 建的 junction 不需要管理员权限，
  以前可以拿它把"看起来在界内"的路径指到界外；现在会被拒，且拒绝文案把**物理落点**打出来。
- 不存在的路径退化为"逐级上溯到最近的存在的祖先再拼回剩余段"，因此**不会**因为文件还没生成被误拒。
- **残余风险如实标注**：不防 TOCTOU（校验通过后、打开文件前链接被替换）。威胁模型是 agent 误操作，不是对抗者。

### `.ioc` 还原原子化 + 备份完整性核对（R-C3）

- `backup` 成功后额外落一份旁路摘要 `<name>.ioc.bak.sha256`（原子写）。
- `restore` 改为**两阶段**：先全量校验所有 `.bak` 的摘要（任何一份不合格即整体拒绝，此时**一个 `.ioc` 都没被动过**），
  再逐个 `mkstemp` + `os.replace` 原子替换。杜绝"前两个工程被还原、第三个是坏备份"的半途状态。
- 摘要不一致 → 退出码 `2` + `[ioc_backup][integrity] 备份疑似被篡改或部分写入`，`.ioc` 一个字节不动。
- 无摘要的旧版备份仍可还原，但 stdout 会打 `[ioc_backup][warn] 缺少完整性摘要（旧版备份），已跳过校验`。

### 文档

- `verify_generation` 的工具描述与 `SKILL.md` §1.3 补充：**`report_md` 会写 Markdown 文件**，`read_only` 下也允许（属证据输出），路径仍受白名单校验。
- `references/regen-exit-codes.md` 增一节：`regen.sh` 的退出码 `2` 也可能是"备份完整性校验失败"，`regen.sh` 本身不专门分支（两种失败的正确续作都是"别信备份，改用 git"）。

## 已知限制

1. **TOCTOU 不防**：校验通过后、实际打开文件前，链接被替换的情形不在防御范围内（威胁模型见上）。
2. **旧版备份缺摘要时这层检测不生效**：0.7.0 之前生成的 `.ioc.bak` 没有 sidecar，仍能还原但只给警告。
   重新跑一次 `ioc_backup` 即可补上摘要。
3. **npm 包不含 `package-lock.json`**（本仓 `.gitignore:49` 忽略），CI 因此用 `npm install`；依赖 `@modelcontextprotocol/sdk` 在 `package.json` 钉的是精确版本 `1.32.2`。
